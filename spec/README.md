# API spec

`openapi.json` is the OpenAPI spec for the Checkout Page seller API (the `/v1` API you call
with an API key). It describes every endpoint, request body and response the tools in this
repo support.

## Where it comes from

The spec is generated by the Checkout Page API itself. Production serves it at
https://api.checkoutpage.com/docs/seller-api/v1/swagger.json, and the public API reference at
[docs.checkoutpage.com](https://docs.checkoutpage.com) is built from the same source.

The copy here is committed so builds are repeatable and every change to the API surface shows
up as a reviewable diff.

## How a refresh is done

There are two kinds of refresh:

- **Full refresh**: replace `openapi.json` with the production spec. This brings the file in
  line with the live API.
- **Partial refresh**: for an API change that is not live yet, copy in only the paths and
  schemas that change touches, and leave everything else as it is. A full refresh follows once
  the change is live.

After either one, run this from the repo root:

```bash
pnpm generate:types
```

This rewrites `openapi.json` in a stable form (keys sorted, pretty-printed) so changes diff
line by line, then regenerates the JavaScript types and the
[Postman collection](../postman/README.md). Commit the rewritten spec and the regenerated
`postman/` files. To regenerate only the Postman files, run `pnpm generate:postman`.

## Every language uses it

Each language in this repo generates its types or client code from this one file. A spec
change is regenerated, tested and released for every language it affects, so the tools stay
in step with each other and with the API.
